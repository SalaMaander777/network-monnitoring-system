## Решения, принятые при реализации

- Цепочка Spring Boot по умолчанию до T1.05: без пользователя 401 с пустым телом, `POST` без CSRF 403 с пустым телом (проверено прототипом). `ApiErrorHandler` пробрасывает `AccessDeniedException` и `AuthenticationException` к фильтру безопасности, а не превращает их в 500.
- Ограничение на параметр метода (Spring 7 даёт `HandlerMethodValidationException`): поле берётся из пути (например `checks[1].port`), а не из имени Java-параметра. Ловушка была в самом §5.1, architect уточнил §5.1.
- Строгий разбор параметров и общий код `DATA_CONFLICT` для непредусмотренных нарушений БД: решения architect, ждут подтверждения заказчика (реестр A-24, A-25).
- Начатый ответ: обрывы клиента и таймауты SSE не пишут `ERROR`, `AsyncRequestTimeout` даёт 503. Правило «начатый ответ + `IOException` в цепочке → `DEBUG`» скрывает и серверный ввод-вывод после начала ответа (реестр A-26).
- Тест блокировки: `lock_timeout=0` даёт тайм-аут около 31 с без зависания сборки.
