# ТЗ: система мониторинга сетевого оборудования

2 нояб. 2026 г. · @Ivan

## Цель и контекст

Нужна браузерная система мониторинга сетевого и радиооборудования, которая полностью работает без интернета. Центр управления большой сети, оборудования сотни единиц, расположено по Москве и области.

Главные сценарии:

1. Дежурный открывает карту и сразу видит, какие устройства в норме, а какие нет.
2. При проблеме появляется тревога, дежурный принимает её в работу, и это остаётся в журнале.
3. Администратор добавляет и правит оборудование в базе и выгружает базу в Excel.

Этот документ задаёт требования для агентов, которые будут реализовывать систему по частям. Любой факт об оборудовании, который здесь помечен как неподтверждённый, агент не выдумывает, а отмечает в отчёте.

## Ограничения и среда

Главное ограничение: в сети нет интернета, поэтому всё, что нужно системе, лежит локально.

- **Офлайн везде.** Никаких CDN, внешних API, веб-шрифтов, иконок и карт из интернета. Проверка приёмки: система работает при отключённом внешнем доступе.
- **Один сервер во внутренней сети, клиент в браузере.** На рабочие места ничего не устанавливается.
- **Windows везде** (рабочие места на Windows 7, 10 и 11, Linux нет). Сервер ставится на Windows 10, 11 или Windows Server, не на Windows 7: она давно вне поддержки. Работу Java 17 или 21 на выбранной версии Windows агент проверяет сам, надёжного подтверждения для Windows 7 не найдено. Агент описывает нужные права и правила брандмауэра Windows для веб-порта и приёма трапов.
- **Агенты не имеют доступа к реальному оборудованию.** Проверки разрабатываются против эмуляторов и заглушек. Реальные OID, порты и команды задаются профилями, которые правятся без перекомпиляции.
- **Сборка без интернета.** Зависимости проекта должны ставиться на машине без доступа к репозиториям (локальный репозиторий или vendoring).

## Технологический стек

Стек рекомендуемый. Агент может предложить замену, если обоснует её и сохранит требование офлайн.

| Слой | Выбор | Примечание |
|---|---|---|
| Бэкенд | Java 17 или 21, Spring Boot | Основной язык разработчика |
| База | PostgreSQL | SQLite допустим только для прототипа |
| SNMP | SNMP4J | Опрос и приём трапов |
| Excel | Apache POI | Выгрузка в .xlsx |
| Карта | Leaflet (MapLibre требует WebGL, на старых ПК это риск) | Все файлы библиотеки лежат на сервере |
| Тайлы | OpenStreetMap, Москва и область, формат MBTiles или PMTiles | Свой тайл-сервер, заранее скачанные данные |
| Живые обновления | WebSocket или SSE | Статусы на карте меняются без перезагрузки |

Всё, что нужно скачать заранее и положить локально: JS и CSS библиотеки, шрифты, иконки, данные карты, MIB-файлы Cisco и Infinet, руководства R&S.

## Типы устройств и способы проверки

Каждому типу устройства соответствует профиль: набор проверок и их параметры. Подтверждённое закладывается сразу, неподтверждённое делается настраиваемым полем профиля и уточняется на реальном устройстве (снимок snmpwalk).

| Тип | Способ проверки | Подтверждено | Не подтверждено |
|---|---|---|---|
| Cisco Catalyst 2960 | ping, SNMP, трапы | CPU: cpmCPUTotal5minRev, 1.3.6.1.4.1.9.9.109.1.1.1.1.8. Память: CISCO-MEMORY-POOL-MIB. Порты: ifOperStatus, физические порты отбирать по ifDescr (ifNumber включает виртуальные и стековые интерфейсы) | Температура: у многих 2960 нет датчика, OID может вернуть пусто. Не делать обязательной |
| Cisco 2911 | ping, SNMP, трапы | Работает обычный набор IOS, CPU тот же OID | Специфичные OID не найдены, проверить на устройстве |
| Infinet R5000 | ping, SNMP, трапы | SNMP-агент по умолчанию выключен, включается в настройках устройства. AQUAMINT-MIB, база 1.3.6.1.4.1.3942.1.1.5, таблицы узлов и линков MINT. Трапы: потеря соседа, смена частоты радио, linkEvent | Точные OID уровня сигнала и битрейта. MIB брать у Infinet. MIB линейки InfiLINK XG не использовать, это другая серия |
| R&S ESMD, EB500, DDF255 | ping, проверка TCP-порта управления, запрос SCPI *IDN? | Управление по LAN через SCPI. Типичные порты R&S: 5025 и 5125 (сокет), 111 (VXI-11), 4880 (HiSLIP) | Рабочий порт конкретных приборов. Наличие SNMP. Порт и команды вынести в поля профиля |
| Компьютеры Windows | ping, проверка TCP-порта (например, RDP 3389) | Работает без агента на машине | Загрузка, диск, память (WMI, WinRM или агент) отложить на потом |
| Старое оборудование | ping | — | — |

SNMP: версия v2c обязательна, v3 желательна. Секреты (community, учётные данные v3) хранятся отдельно от данных устройства.

## Модель данных

Новый тип оборудования должен добавляться данными, без переписывания кода.

| Сущность | Основные поля |
|---|---|
| Устройство | название, тип, IP, широта, долгота, адрес или описание, профиль проверок, текущий статус, примечание, дата добавления |
| Профиль проверок | название, список проверок. У проверки: вид (ping, SNMP, TCP, SCPI, приём трапа), параметры (OID, порт, команда), интервал, таймаут, пороги |
| Результат проверки | устройство, проверка, время, значение, статус |
| Событие | устройство, время, тип (смена статуса, трап, действие пользователя), описание |
| Тревога | устройство, уровень, причина, время начала, время окончания, кем и когда принята, комментарий |
| Пользователь | логин, хэш пароля, роль |
| Секреты доступа | SNMP community или учётные данные v3, привязка к устройству или группе |

Роли: просмотр, редактирование, администратор. Секреты не попадают в Excel-выгрузку, логи и ответы API.

## Функциональные требования

### Карта

- Офлайн-карта Москвы и области, маркеры устройств, цвет маркера по статусу.
- Клик по маркеру открывает карточку устройства: данные, статус, последние события.
- Поиск по названию и IP, фильтры по типу и статусу.
- Группировка маркеров при мелком масштабе.
- Добавление устройства: выбор точки на карте и заполнение формы.

### База оборудования

- Создание, правка, удаление устройств. Удаление не стирает историю событий.
- Проверка IP и координат, запрет дубля IP.
- Выгрузка всей базы в Excel (.xlsx), с учётом текущих фильтров. Обязательное требование.
- Загрузка из Excel для первичного наполнения сотнями устройств, с отчётом об ошибочных строках. Желательное требование, уточнить у заказчика.

### Обзор и журнал

- Сводка: количество устройств по статусам, список активных тревог.
- Журнал событий с поиском и фильтрами, срок хранения настраивается.

### Доступ

- Вход по логину и паролю, права по ролям из раздела о модели данных.

## Статусы и тревоги

У устройства один из четырёх статусов: норма, предупреждение, авария, нет данных.

- **Задержка перед тревогой.** Тревога возникает после нескольких подряд неудачных проверок, а не после одной потерянной. Число проверок настраивается в профиле. Агент предлагает значение по умолчанию и помечает его как допущение.
- **Пороги.** Для числовых параметров (например, загрузка CPU) задаются пороги предупреждения и аварии в профиле.
- **Защита от мигания.** Статус не должен переключаться туда и обратно при значении у самой границы порога.
- **Квитирование.** Дежурный принимает тревогу в работу, указывая комментарий. Фиксируется, кто и когда принял. Тревога закрывается сама, когда устройство восстановилось, запись остаётся в журнале.
- **Трапы.** Приём SNMP-трапов, чтобы о проблеме Cisco и Infinet было известно сразу, а не при следующем опросе. Для Infinet: потеря соседа, смена частоты, linkEvent. Для Cisco: linkUp и linkDown. Агент учитывает, что приём трапов требует свободного UDP-порта и прав на него.
- **Уведомления.** Только внутри интерфейса: цвет маркера, счётчик и список тревог, звуковой сигнал по настройке. Почта и SMS не входят в объём, пока нет внутреннего шлюза.

## Нефункциональные требования

- **Масштаб.** Сотни устройств. Точное число неизвестно, поэтому опрос делается параллельным, с таймаутами, и один зависший прибор не задерживает остальных.
- **Живучесть.** После перезапуска сервера состояние, тревоги и журнал сохраняются. Запуск как служба Windows при старте системы.
- **Безопасность.** Вход по паролю, пароли хранятся только в виде хэшей. Секреты доступа к устройствам не попадают в логи, Excel и ответы API. HTTPS во внутренней сети желателен (самоподписанный сертификат), решение за заказчиком.
- **Журнал действий.** Фиксируется, кто что изменил в базе и кто принял какую тревогу.
- **Резервная копия.** Простая выгрузка и восстановление базы одной командой.
- **Браузеры.** На части рабочих мест стоит старый Internet Explorer, он не поддерживается. Нужный браузер ставится установщиком из комплекта поставки, офлайн-установщики входят в дистрибутив. На Windows 7 последняя версия Firefox с её поддержкой это 115 ESR, а Chrome и Edge Windows 7 уже не поддерживают. Поэтому интерфейс должен работать в Firefox 115 ESR и в современных Chrome или Edge: без новейших возможностей JavaScript, с проверкой на обоих.
- **Нагрузка на сеть.** Интервалы опроса настраиваются по типу устройства, чтобы мониторинг не создавал заметной нагрузки на сеть управления.

## Правила для каждого агента

- Не выдумывать OID, порты и команды. Нет подтверждения значит «не подтверждено» в отчёте.
- Не обращаться к интернету во время работы системы и не подключать внешние ресурсы.
- Всё специфичное для оборудования выносить в профили, а не в код.
- Писать тесты на эмуляторах и заглушках, реального оборудования нет.
- В конце каждой задачи: что сделано, что не проверено, что нужно от человека.
