# ТЗ v2: система мониторинга сетевого и радиооборудования

Версия 2.2 · 2 нояб. 2026 г. · заказчик @Ivan · статус: утверждено
Исходный текст ТЗ: `docs/archive/TZ-v1.md`. При расхождении действует этот документ, изменения вносятся только с согласия заказчика.

## 1. Цель

Браузерная система мониторинга сотен единиц сетевого и радиооборудования в Москве и области. Система полностью работает без интернета.

Главные сценарии:

1. Дежурный открывает карту и сразу видит, какие устройства в норме, а какие нет.
2. При проблеме появляется тревога, дежурный принимает её в работу, это остаётся в журнале.
3. Администратор ведёт базу оборудования и выгружает её в Excel.

## 2. Ограничения

| ID | Ограничение |
|---|---|
| C-1 | Во время работы никаких обращений в интернет: CDN, внешних API, веб-шрифтов, иконок и карт. |
| C-2 | Один сервер во внутренней сети. На рабочие места ничего не ставится, кроме браузера из комплекта при необходимости. |
| C-3 | Сервер: Windows 10, 11 или Windows Server. Windows 7 как сервер не поддерживается. Linux не используется. |
| C-4 | Клиенты: Windows 7 с Firefox 115 ESR; Windows 10 и 11 с современным Chrome или Edge. Internet Explorer не поддерживается. |
| C-5 | Сборка возможна на машине без доступа к репозиториям (локальный репозиторий зависимостей). |
| C-6 | У разработки нет реального оборудования: проверка на эмуляторах. OID, порты и команды живут в профилях и меняются без перекомпиляции. |
| C-7 | Факт об оборудовании без подтверждения не выдумывается и получает пометку «не подтверждено». |

### Типы устройств и способы проверки

Подтверждённое закладывается в начальные профили сразу. Неподтверждённое становится настраиваемым полем профиля и уточняется на реальном устройстве (снимок snmpwalk).

| Тип | Способ проверки | Подтверждено | Не подтверждено |
|---|---|---|---|
| Cisco Catalyst 2960 | ping, SNMP, трапы | CPU: cpmCPUTotal5minRev, 1.3.6.1.4.1.9.9.109.1.1.1.1.8. Память: CISCO-MEMORY-POOL-MIB. Порты: ifOperStatus, физические порты отбирать по ifDescr (ifNumber включает виртуальные и стековые интерфейсы) | Температура: у многих 2960 нет датчика, OID может вернуть пусто. Не делать обязательной |
| Cisco 2911 | ping, SNMP, трапы | Работает обычный набор IOS, CPU тот же OID | Специфичные OID не найдены, проверить на устройстве |
| Infinet R5000 | ping, SNMP, трапы | SNMP-агент по умолчанию выключен, включается в настройках устройства. AQUAMINT-MIB, база 1.3.6.1.4.1.3942.1.1.5, таблицы узлов и линков MINT. Трапы: потеря соседа, смена частоты радио, linkEvent | Точные OID уровня сигнала и битрейта. MIB брать у Infinet. MIB линейки InfiLINK XG не использовать, это другая серия |
| R&S ESMD, EB500, DDF255 | ping, проверка TCP-порта управления, запрос SCPI `*IDN?` | Управление по LAN через SCPI. Типичные порты R&S: 5025 и 5125 (сокет), 111 (VXI-11), 4880 (HiSLIP) | Рабочий порт конкретных приборов. Наличие SNMP. Порт и команды вынести в поля профиля |
| Компьютеры Windows | ping, проверка TCP-порта (например, RDP 3389) | Работает без агента на машине | Загрузка, диск, память (WMI, WinRM или агент) отложить на потом |
| Старое оборудование | ping | — | — |

## 3. Как читать перечень фич

- **Приоритет:** M обязательно, без этого система не принимается. S желательно: делается в той же задаче, но не блокирует приёмку и может быть снято заказчиком.
- **Источник:** И из исходного ТЗ. Д добавлено при проработке, потому что без этого требование ТЗ не работает.
- **Задача:** номер задачи из раздела 11.

## 6. Правила статусов

В каждом профиле одна проверка отмечена как **основная** (обычно ping). Статус устройства равен худшему из результатов обязательных проверок в порядке: авария, предупреждение, нет данных, норма.

| Статус | Условие |
|---|---|
| Авария | Основная проверка не прошла N раз подряд, либо значение перешло порог аварии |
| Предупреждение | Основная проверка проходит, но другая обязательная не прошла N раз подряд (например, SNMP не отвечает при живом ping), либо значение перешло порог предупреждения, либо сработало правило трапа |
| Нет данных | Устройство только добавлено, мониторинг отключён или результатов нет дольше 3 интервалов |
| Норма | Все обязательные проверки успешны и значения в пределах порогов |

Необязательная проверка (например, температура 2960) статус не меняет. Восстановление требует M успешных проверок подряд, а значение должно уйти от порога на величину гистерезиса.

**Трапы.** Трап сразу пишется в журнал. Тревогу он создаёт по правилу профиля без задержки N, потому что цель трапа в немедленном оповещении. Тревогу от трапа закрывает парный трап (например, linkUp) или успешный опрос. Смена частоты по умолчанию только событие.

| ID | Требование | Как проверяется |

| NFR-05 | Интерфейс работает в Firefox 115 ESR и современных Chrome и Edge | Автотесты в обоих браузерах |
| NFR-06 | Ни одного внешнего запроса из браузера и с сервера | Тест с блокировкой внешней сети и записью запросов |

## 10. Технические решения

Архитектор может предложить замену с обоснованием, сохранив требование офлайн.

| Слой | Решение | Причина |
|---|---|---|
| Бэкенд | Java 21, Spring Boot, среда Java в комплекте | Основной язык разработчика; совместимость с выбранной Windows проверяется при поставке |
| База | PostgreSQL в комплекте поставки | SQLite только для прототипа |
| Миграции схемы | Flyway | Обновление без ручных правок БД |
| SNMP | SNMP4J | Опрос и трапы |
| Excel | Apache POI | Выгрузка и загрузка |
| Карта | Leaflet и плагин группировки маркеров, локальные файлы | MapLibre требует WebGL, на старых ПК это риск |
| Тайлы | Растровые PNG в MBTiles | Leaflet показывает растр без дополнений; MBTiles это один файл SQLite |
| Живые обновления | SSE | Поток идёт только от сервера к браузеру, действия пользователя идут через REST |
| Фронтенд | Без внешних загрузок; весь код и ресурсы отдаёт сервер; JavaScript проверяется в Firefox 115 ESR | C-1, C-4 |

### Что готовится заранее на машине с интернетом

| Материал | Источник | Замечание |
|---|---|---|
| Зависимости Maven или Gradle | Центральный репозиторий | Переносятся локальным репозиторием |
| Leaflet и плагин группировки, шрифты, значки, звук | Их проекты, только с открытой лицензией | Лежат в проекте |
| Тайлы Москвы и области | Выгрузка данных OSM, тайлы рендерятся самостоятельно | Массовое скачивание с серверов tile.openstreetmap.org запрещено их правилами. Нужно выбрать максимальный масштаб и оценить размер |
| MIB Cisco и Infinet, руководства R&S | Производители | Если нет в открытом доступе, предоставляет заказчик |
| Java, PostgreSQL для Windows, установщики браузеров | Официальные сайты | Версии фиксируются в документации |

### Известные риски реализации

- **Порт трапов.** Порт UDP 162 может занимать служба Windows «SNMP Trap». Инструкция описывает её отключение, порт настраивается.
- **Ping на Windows.** Способ ping в Java зависит от ОС и прав. Выбор и проверка на Windows обязательны, результат на macOS не считается доказательством.
- **Секреты в резервной копии.** Файл ключа хранится отдельно от дампа; инструкция описывает, как сохранить оба.

## 11. Задачи и приёмка

Порядок: задача 1 первая; 2, 3 и 7 параллельно после неё; 4, 5 и 6 после 3; задача 8 последняя.

| № | Задача | Агент | Фичи | Приёмка |
|---|---|---|---|---|
| 1 | Каркас и база | backend-core | AUTH, DEV (кроме 08), PRF, SEC-01..05, LOG-04 | Устройство создаётся, правится, удаляется, права по ролям работают |
| 2 | Офлайн-карта | map-frontend | MAP | Карта открывается при отключённом интернете, маркер ставится кликом |
| 3 | Опрос ping и TCP | polling-engineer | POLL, DEV-08, RS-04, RS-05, LOG-01..03, ALM-01 | Отключение заглушки меняет статус на карте |
| 4 | SNMP | snmp-engineer | SNMP | Эмулятор отдаёт значения и трапы, они видны в системе |
| 5 | Проверки R&S | polling-engineer | RS-01..03 | Эмулятор с ответом на `*IDN?` определяется как доступный |
| 6 | Тревоги | alarm-engineer | ALM, OVR | Тревога возникает после заданного числа неудач, принимается, закрывается при восстановлении |
| 7 | Excel | excel-engineer | XLS | Файл открывается в Excel, секретов нет |
| 8 | Интеграция и сборка | windows-packager | OPS, SEC-06 | Чистые машины без интернета (клиенты Windows 7 и Windows 10 или 11): установка по инструкции, всё работает |

Фича считается готовой, когда выполнен её критерий, задача прошла контроль, описанный в `CLAUDE.md`, и в отчёте перечислены непроверенные места.

**Сквозная приёмка.** На чистой системе: установка, вход, добавление устройства на карте, отключение эмулятора, появление тревоги после N неудач, квитирование, восстановление и закрытие тревоги, запись в журнале, выгрузка в Excel, перезапуск сервера, резервная копия и восстановление. Всё без внешней сети.

**Обязательная проверка человеком.** Поставка на настоящих машинах с Windows (сервер, клиенты Windows 7 и 10 или 11), значения на реальном оборудовании, открытие файла в настоящем Excel.

## 12. Вне объёма текущей версии

- Почта и SMS: пока нет внутреннего шлюза.
- Загрузка ПК, диск и память через WMI, WinRM или агент.
- Сервер на Windows 7 или Linux, Internet Explorer.
- Режим обслуживания (плановые работы без тревог): заказчик решил, что он не нужен.
- Графики: заказчик отложил их на потом. Результаты проверок сохраняются (POLL-05), поэтому добавить графики можно будет без переделки сбора данных, в пределах срока хранения результатов.

Не включено, потому что нет в исходном ТЗ, и может быть добавлено заказчиком: топология связей на карте, автообнаружение устройств, вход через Active Directory, резервирование сервера.

## 14. Правила для каждого агента

- Не выдумывать OID, порты и команды. Нет подтверждения значит «не подтверждено» в отчёте.
- Не обращаться к интернету во время работы системы и не подключать внешние ресурсы.
- Всё специфичное для оборудования выносить в профили, а не в код.
- Писать тесты на эмуляторах и заглушках.
- В конце каждой задачи: что сделано, что не проверено, что нужно от человека.
