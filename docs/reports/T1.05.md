## Решения, принятые при реализации

- Цепочка безопасности по §5.1 (блок «Безопасность»): анонимный запрос к `/api/**` получает 401 `AUTH_REQUIRED` в JSON, `/index.html` перенаправляется на `/login.html`, неверный вход даёт 401 `AUTH_FAILED` с одним текстом для всех причин, CSRF без токена или с чужим токеном даёт 403 `CSRF_INVALID`, отказ по роли даёт 403 `FORBIDDEN`. Тела ответов пишутся байтами через `JsonMapper` (`JsonAuthHandlers`).
- Доступ задаётся `@PreAuthorize` на методах. `SecurityConfig` содержит только публичный список из §5.1, правил по отдельным ресурсам нет.
- Фиксация сессии: id сессии меняется при входе. Проверено только на Tomcat (`LoginTest.sessionIdChangesOnLogin` через `RestartableApp` и `HttpClient`), `MockMvc` смену id не воспроизводит.
- Срок сессии до T1.08 — умолчание Spring Boot (30 мин простоя). Значение `session.timeout_minutes=720` пока не действует (A-28).
- `/error`: `ApiErrorController` отдаёт формат §5.1 и ничего не пишет, если ответ уже начат. `ArchitectureTest` исключает его по полному имени класса: без исключения правило п. 3 падало. Исключение отказа фильтра (`FailingFilter`) до Spring Security даёт 500 `INTERNAL_ERROR` в JSON (`ErrorPageTest.filterExceptionGoesToErrorPage`).
- Кросс-параметрические ограничения (Bean Validation на методе) запрещены на методах контроллеров: Spring 7.0.10 их без ограничения параметра не применяет. Совместная проверка пишется кодом через `ApiException.validation(...)` с `field: null`. Тест `crossParameterAloneIsIgnoredBySpring` фиксирует это поведение; его падение после обновления Spring сообщается architect.
- Тело `@RequestBody` верхнего уровня — всегда объект (`ArchitectureTest`, правило `objectBody`, проверено на `ListBodyController`).
- `CurrentUser` лежит в `common.security`. Его `toString` не выводит хэш пароля.
- Исключение `UserDetailsServiceAutoConfiguration` в `NetMonitoringApplication` осталось на месте (файл не менялся, см. A-05).

По сообщениям architect и QA; в этом отчёте тесты заново не запускались.
- Аудит (шаг 3): нарушений нет.
- Мутации, которые тесты поймали: CSRF выключен; `anyRequest().permitAll()`; разный текст для неизвестного логина; `sessionFixation none`; `/error` без ERROR-диспетчеризации.

- Ревью: принято без возвратов, кругов возврата 0. По байткоду Spring Security 7.1.2 подтверждено: фиктивный BCrypt для неизвестного логина и проверка пароля для отключённого пользователя (защита от перечисления по времени); пароль длиннее 72 байт при входе даёт 401; нет open redirect; анонимный запрос не создаёт сессию; выход удаляет `JSESSIONID` и `XSRF-TOKEN`; сессии не переживают перезапуск.
