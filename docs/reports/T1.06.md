## Решения, принятые при реализации

- Запись в той же транзакции: `@Transactional(propagation = MANDATORY)` на `record` обоих сервисов. Вне транзакции вызова будет `IllegalTransactionStateException`. Откат вызывающего убирает и `audit_log`, и `event`. Если вызывающий перехватит исключение из `record`, его транзакция всё равно откатывается (`UnexpectedRollbackException` при фиксации). Проверено прототипом architect и тестами.
- Публикации нет: журналы не шлют событий Spring и SSE. Читатели видят запись после фиксации транзакции вызывающего.
- `Instant` в SQL передаётся как `OffsetDateTime` в UTC. JSON в `jsonb` передаётся строкой с `?::jsonb`, IP как строка `getHostAddress()` с `?::inet` (без DNS).
- `SecretFieldGuard` лежит в `common/json`, а не в `audit`: его вызывают оба модуля, `audit` и `journal` (§2.2 п. 1; модули не вызывают друг друга).
- Хранение (удаление по сроку) не входит в задачу: `event` удаляет T3.16, `audit_log` — T3.23 (см. A-36 о зоне T3.23).
- Помощники тестов не меняют состояние общего контекста (§12.2). `Api` берёт настоящий токен через `csrfToken()` (`GET /api/auth/csrf`). Вызов `SecurityMockMvcRequestPostProcessors.csrf()` навсегда заменяет хранилище токенов в `CsrfFilter` кешированного контекста. После первого теста с `Api` в том же контексте ломались `CsrfTest` и `LoginTest` (8 падений в порядке `alphabetical`). Причина подтверждена architect по байткоду и зондом. Обход через `@DirtiesContext` не принят: он не устраняет причину. `@DirtiesContext` на `AuditApiTest` не ставится. Для регрессии добавлен `ApiSelfTest`.
- Правило §12.2 дополнено: помощники и тесты не меняют состояние общего контекста; `csrf()` и `@DirtiesContext` не допускаются как обход побочных эффектов (карточка T1.06, «Запрещено»).

## Проверки

- Команда карточки `mvn -B -pl server -am test -Dtest='SecretFieldGuardTest,EventJournalWriteTest,AuditLogTest,AuditApiTest,ApiSelfTest,ArchitectureTest'`, затем полный `mvn -B -pl server -am test` в порядках `alphabetical` и `reversealphabetical`: по сообщению QA, полный прогон модуля `server` 99 тестов, оба порядка зелёные, `offline-verify` зелёный. В этом отчёте тесты заново не запускались.
- Проверка критериев карточки (по сообщению QA): `grep -rn 'csrf()' server/src/test` находит только javadoc `Api`; `@DirtiesContext` в тестах только в `SmokeTest`; запись в транзакции вызывающего (`MANDATORY`).
- Аудит (шаг 3): нарушений нет.
- Мутации, которые тесты поймали: `REQUIRED` вместо `MANDATORY` (две мутации, оба сервиса); `SecretFieldGuard` без вложенности; `SecretFieldGuard` с учётом регистра; `orderBy` без tie-breaker; доступ `OPERATOR` к `/api/audit`; `csrf()` вместо `csrfToken()`.
- Ревью (шаг 5): принято без возвратов. Проверено на PostgreSQL 18.6 и разбором кода: самовызова нет; `UnexpectedRollbackException`; глубина рекурсии `SecretFieldGuard`; SQL (параметры, `?::jsonb`, `?::inet`); `Clock`; `csrfToken`.
- Неблокирующие замечания ревью, которые architect разносит сейчас (см. A-38…A-42): тупик трапов, IPv6 с зоной в `?::inet`, NUL в `jsonb`/`text`, `/api/audit` с датой вне диапазона, `SecretFieldGuard` только по точным именам, `count`/`page` без общей транзакции, размер `oldValue`/`newValue`.

## Не проверено

- Windows: не проверялось (A-21, A-07…A-09).
- Многопоточная обработка трапов: проверена только модель на SQL, не реальные потоки (A-38).
- Тупик трапов (`FOR KEY SHARE` от FK `event.device_id` и `FOR UPDATE` в пересчёте статуса) воспроизведён на PostgreSQL 18.6 моделью. В живой системе не проверен (A-38).
- IPv6 с зоной (например `fe80::1%eth0`) в `?::inet` не подтверждён (A-39).
- Символ NUL в значениях `jsonb` и `text` не подтверждён (A-40).
- `GET /api/audit` с датой вне диапазона по ревью даёт 500 вместо 400. Исправление не сделано (A-41).
- `count` и `page` выполняются без общей транзакции, размер `oldValue`/`newValue` не ограничен (A-42).
- `SecretFieldGuard` защищает только точные имена полей. Варианты с разделителями, `secret`, `token`, `apiKey` и другие не закрыты, `description` не очищается (A-37).
- Запись журнала при входе и выходе не делается: ТЗ этого не требует (карточка T1.06, «Запрещено»). Журнал доступа — задача 8 (A-29).
